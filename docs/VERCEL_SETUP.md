# Vercel setup — Supabase Postgres + private Blob storage

Do everything below from your own terminal and the Vercel dashboard.
Never paste tokens or passwords into chat, issues, or the repo.
`.env.local` is gitignored — secrets live there and in Vercel env vars only.

## 1. Link the project (once)

```bash
cd /Users/homegrownentllc/clip-mvp
vercel link
```

## 2. Connect Supabase Postgres (Neon is out — Supabase is the database)

Option A — Supabase dashboard (recommended, you already use Supabase):
1. Open your Supabase project → Project Settings → Database.
2. Copy the pooled connection string (port 6543, Transaction mode) — this is
   `DATABASE_URL`. Copy the direct string (port 5432, Session mode) — this is
   `DIRECT_URL` for migrations.
3. In Vercel: project → Settings → Environment Variables, add both for
   Production, Preview, and Development. Never paste them in chat.

Option B — Marketplace: Vercel Marketplace → Supabase → Install → connect
this project (include Development), then `vercel env pull`. Confirm both
`DATABASE_URL` and a direct URL are present.

Then push the schema and seed the two logins:

```bash
vercel env pull
npx dotenv -e .env.local -- npx prisma db push
HUSBAND_PASSWORD='<strong unique>' WIFE_PASSWORD='<strong unique>' \
  npx dotenv -e .env.local -- node prisma/seed.mjs
```

**Both URLs are mandatory, and they are not interchangeable.** `prisma/schema.prisma`
declares `url = env("DATABASE_URL")` and `directUrl = env("DIRECT_URL")`.
Prisma does **not** fall back to `DATABASE_URL` when `directUrl` is missing — it
fails with `P1012` (verified). So:
- `DATABASE_URL` → pooled, port **6543**, `?pgbouncer=true` — the app at runtime.
- `DIRECT_URL` → direct, port **5432** — `db push`, `db:rls`, anything DDL.

`prisma generate` (the `postinstall` step on Vercel) works with neither variable
set, so adding `directUrl` does not break the build.

Lock the database down for the public API roles — Supabase exposes `public` over
PostgREST to anyone holding the anon key, and this app never uses that path:

```bash
npx dotenv -e .env.local -- bash scripts/apply-rls.sh   # or: npm run db:rls
```

Expect `Script executed successfully`. It enables RLS on all 7 tables with zero
policies and revokes `anon` / `authenticated`. It is idempotent and a deliberate
no-op on plain Postgres. Re-check with the query at the bottom of
`prisma/rls-lockdown.sql`: 7 rows with `rls_enabled = true`, `policies = 0`.

Rules: production passwords are set as shell env vars at seed time, never
written to files, never committed, never reused from dev. Dev passwords
generated by earlier local seeds stay on this machine only (`.data/`,
gitignored, excluded from backups).

Verify in the dashboard: project → Storage → database → Database tab should
list `User`, `BrandSetting`, `MediaAsset`, `ClipProject`, `Transcript`,
`RenderJob`, `ProcessingLog`. Two rows in `User`, zero secrets anywhere.

## 3. Provision the private Blob store

```bash
vercel blob create-store street-ethics-clips --access private --yes
vercel env pull
```

Confirm `.env.local` contains `BLOB_READ_WRITE_TOKEN` (required for
`handleUpload` client-token generation) and `BLOB_STORE_ID`.
Dashboard path: project → Storage → Create Storage → Blob → Private →
tick "Add a read-write token env var", include Development in the connection.

Private-store consequence (already planned, Section 4): the current
`/api/downloads/[renderId]` 302-redirect assumes a fetchable URL. With a
private store, downloads must be served through the app (`get()` / presigned
`getDownloadUrl`) instead of redirecting. Until that lands, treat the
download button as pending and preview renders in the dashboard player via
the same server-mediated path.

## 4. Deploy and verify

```bash
vercel deploy
```

Then run the README HTTP sequence against the deployment URL instead of
localhost: login → small upload (201 `stored:true`) → 5.9MB upload
(413 `use_client_upload`) → token issuance → asset-ID validate
(`validated`) → foreign asset (404). Paste the status codes back here.

## 5. Region + cost notes

- Create the Supabase project and Blob store in the region closest to your
  Vercel project region (dashboard → project → Settings) to cut latency.
- Runtime traffic goes through the pooler (6543); only DDL uses the direct port.
  That is fine for 2 users. If you later add creators, add Prisma Accelerate or
  a serverless driver before opening signups — a transaction pooler plus Prisma
  is a known ceiling, not an infinite one.
- Blob egress bills on delivery: keep previews server-mediated and capped at
  60s clips per the app limits.
